# Depth Matrix

Depth Matrix is a dockable comparison view for synchronized Binance BTCUSDT Spot and USD-M perpetual books. Add it from the bottom toolbar. Its settings let you order or remove columns, choose a fixed USDT bucket width, adjust venue width, display BTC quantity or USDT notional labels, compare independent or shared scales, and highlight large rows. Layout version 5 stores these choices with the Dockview panel.

The active sources are Binance BTCUSDT Spot and Binance BTCUSDT USD-M Perp. The source picker also lists Bybit Spot, Bybit perpetual and Hyperliquid BTC perpetual as unavailable; selecting one never creates sample or borrowed quotes. Up to eight source IDs can be stored, while only the two configured Binance books produce live values.

## Rows and coverage

Price buckets use exact decimal arithmetic and fixed `[low, high)` USDT bounds. The PRICE axis labels each row with its low edge. Bid and ask quantities are retained separately in the same row: a mixed bucket has independent upper/lower strips, and a one-sided bucket uses the full cell height. Each side uses the same full-column width denominator. Bar widths compare normalized BTC quantity in both label modes; switching labels to USDT does not change relative sizes. A shared scale compares all selected venues; a per-venue scale fills each venue's range independently.

The worker preserves the depth collector's side-specific snapshot scope. `observed` means the side has one or more levels in the bucket; `known empty` means the synchronized book covers the bucket and has no levels there; `partial` marks a bucket crossing an outer snapshot/truncation boundary; `unknown` lies outside proved coverage. A sequence gap invalidates the working book and displays syncing until a new checkpoint/snapshot arrives. A stale or disconnected transport retains the last observed quantities but marks the header and side coverage with that state. There is no combined Total column.

Displayed notional is `price × normalized BTC quantity`, in USDT. Cell labels use compact precision and mark positive values below display precision. Hovering any venue cell reports that venue's own bucket quantities, notionals, side coverage and book age; unsupported sources report that synchronized row data is unavailable.

## Data flow and limits

The worker listens to the existing per-market durable `depth-head` stream shared with the heatmap service. If no stream head arrives for five seconds, one bounded health probe per market checks the same collector over HTTP and refreshes the current-book snapshot from its fresh durable head. The panel labels this HTTP snapshot recovery while the stream reconnects; stale health never produces live rows. Probes stop when stream heads return or no widgets remain. Current-book and health proxy requests use a separate connection pool from historical reads. Empty grids show a visible loading, disconnection or timeout explanation and RETRY guidance. On each head it requests only the visible current-book projection from `/market-data/v1/depth-matrix?width=…&low=…&high=…&market=…`; the history gateway routes this to `/v1/depth-matrix` on the selected market collector. The collector advances its bounded book projection only after the corresponding journal batch has been durably inserted. It returns at most 2,000 exact-decimal bucket rows, BTC quantities, USDT notionals, best quotes and side-specific coverage. The default viewport is 160 rows centered around the book mid. Existing `/depth-observations` pagination remains unchanged for historical and Order Wall use and is not used by this panel.

Requests for identical market, width and viewport grids are coalesced. The worker prefetches two adjacent pages around the active viewport, or around its pending target during a page change. It keeps active, pending and neighbor pages within a 64-grid cap (eight widgets, four pages per widget and two supported markets). Center supersedes outstanding scroll requests and waits for the matching viewport before positioning the current mid-price row. Hiding and restoring a dock tab preserves the requested price range and scroll position across the new worker subscription; a late response cannot restore a superseded range. A scroll requests the next viewport before its edge; the panel keeps the current rows and carries further scroll movement into the pending position until every supported source has a fresh, live, same-epoch replacement. It then swaps the shared viewport as one update. Offline, stale, expired or old-epoch data cannot trigger that promotion. Neighbor prefetch is one-shot and isolated from active-feed stale/retry status; a page refresh takes priority once that page becomes active. The worker validates row indices and exact bucket bounds, and emits IPC updates separately from exchange observation cadence. The panel uses one animation frame for native canvas drawing, paints visible rows and marks only changed rows dirty; hidden Dockview panels and a hidden browser document release their matrix subscription. Fixture books are used only when `?fixture=1` is explicitly selected in a development/diagnostic build.

The superseded raw-observation replay implementation was measured on the Raspberry Pi 5 against staging on 2026-10-20. Eight API page fetches had a median of 1.43 s, p95 of 3.53 s and maximum of 4.40 s; final 31- and 38-record page applications took 565 ms and 671 ms. During a separate 68-second headless SwiftShader run, those columns remained stale for the full sample while each source collector's health head was fresh. This is historical evidence for the replaced replay path only.

The compact current-book endpoint was deployed to staging in backend commit `7cabd433197f45cf3ab3bda42376892b3580bde8` on 2026-10-20; only the existing `collector` and `spot-collector` services were rebuilt. The gated live worker test passed for both markets and advanced five Spot and six perpetual head notifications across four compact requests (p50 2.40 s, p95 3.03 s, maximum 3.80 s). A 61.59-second headless Chromium run on the Raspberry Pi 5 host showed live Spot and USD-M columns in both themes. Actual displayed book ages were p50 1.80 s, p95 3.78 s and maximum 5.63 s. Both columns remained marked live; two readings exceeded five seconds by 0.55–0.63 s, consistent with the panel's one-second idle status/age refresh cadence. Spot cursor advanced 2,763,019→2,763,633 and perpetual 7,005,206→7,005,814. The screenshots are `/tmp/depth-matrix-live-final-dark.png` and `/tmp/depth-matrix-live-final-light.png` on the verification host.

After the quiet sample, the displayed cursor and epoch for each source were pinned and independently reconstructed through the existing `/depth-observations` API. All 160 visible rows per source and both best quotes matched. There were no gaps; maximum row-sum differences were below `8e-13 BTC` and `6e-8 USDT`. The 70 compact responses were HTTP 200 and gzip encoded, totalling 219,017 encoded bytes and 1,929,347 decoded bytes; request latency was p50 818 ms, p95 1.72 s and maximum 3.26 s. This is live correctness and freshness evidence for the deployed staging endpoint. It is not a 60 fps or native GPU performance claim: the browser used ANGLE SwiftShader, CDP measured 9.40 seconds of main-thread task time, and instrumented Canvas2D methods accounted for 531 ms over 35,303 calls. Canvas timings cover synchronous API calls, not rasterization or GPU work.

A local synthetic Pi 5 Model B Rev 1.0 benchmark measured `CommittedDepthMatrix.applyCommitted()` with one 5,000-level-per-side seed and 255 deltas carrying eight price updates per side: 12 runs, p50 28.79 ms, p95 110.08 ms, maximum 145.16 ms. A following default 160-row snapshot projection measured p50 1.93 ms, p95 8.47 ms and maximum 16.49 ms. These isolated in-process timings exclude durable writes, the gateway, HTTP and browser drawing; they are code-level workload checks, not live or end-to-end freshness or FPS evidence.

It follows durable heads for both collectors and checks that the returned compact views stay live, but it does not start or restart collectors.
