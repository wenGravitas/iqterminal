# Net Positioning — Estimated

**Net Longs & Shorts** is one native lower-pane indicator. Its Settings dialog has **Show Longs** and **Show Shorts** options, both on by default for new indicators, plus a **Reverse order** option. Longs appear above Shorts by default. Each side has its own signed scale within its band. One set of venue buttons controls both sides; pressed buttons show included venues, and hover or keyboard focus highlights their bars. All venue buttons stay available when a side is hidden or no venue is selected. Estimation inputs, display, labels and side visibility are saved with the chart. Available sources are Binance BTCUSDT USD-M perpetual, Hyperliquid BTC perpetual, and Bybit BTCUSDT USDT perpetual. Bybit recorded data requires the companion server update and additive migration described in [Bybit support](bybit.md). The staging worker reads the recorder API and shares bounded history and polling work for the combined pane. Fixture mode and direct venue connections never stand in for recorder data.

Saved **Net Longs — Estimated** and **Net Shorts — Estimated** instances migrate to the combined indicator. Their venue selections are united. The long-side settings take precedence when the old instances disagree on shared settings; the original normalized per-side settings are retained in the saved configuration for recovery. Each new side-visibility option follows whether its old indicator was present and visible. Saved layouts with just one side keep that side selected; new indicators show both.

Choose **Price + OI** or **Aggressor Flow + OI**. For an observed source interval, the estimator compares the BTC-sized open-interest change between adjacent observations with either the same-feed price direction at the interval boundaries or the same-feed aggressor buy-minus-sell flow. It assigns that signed change to the matching side; neutral direction is shown as unclassified. The application aggregates the recorder's exact decimal quantities into the host candle whose `[open, close)` range contains the source interval's effective end time. An end timestamp exactly on a candle boundary belongs to the candle opening at that boundary.

Source observations arrive at 30-second resolution. **Stacked** is the default: each venue keeps its original signed BTC contribution, positive values accumulate above zero and negative values below zero. Positive and negative totals remain independent; values are never split between signs or converted to absolute amounts. **Grouped** keeps each venue's individual value, including its selected slot when it has no observation for that candle. Longs use green bars and Shorts use red bars on both sides of zero. Each venue keeps a distinct shade within the side's colour, matching the source legend and tooltip. Amount labels use the source colour and sit above positive bars or below negative bars. Stacked venues use separate label rows outside the complete signed stack; scale padding reserves room for the text. Valid saved source-color overrides remain in effect. Each side calculates scale extents from the visible candle range. Changing display, labels or visible sides does not change the worker request or remount the pane. Shared cumulative boundaries round to device pixels to avoid seams.

Only observed source intervals are drawn. A true observed zero is marked at the zero line; a missing or unavailable interval leaves no bar. Partial source coverage uses reduced opacity and remains identified as partial in the tooltip. The panes do not fill gaps or interpolate. The recorder request spans at most four hours, and each method retains at most 2,000 intervals in the worker and shared candle history. The compact source legend has keyboard-focusable buttons that emphasize that source's visible segments. **Auto** value labels use 12px semibold source-tinted text with stronger contrast and round the displayed magnitude to the nearest whole BTC; they appear only when measured text fits the bar width and the available space outside it; **Hover only** waits for a segment hover; **Off** hides labels. Hovering a source bar opens a compact tooltip anchored above that bar, with UTC candle time, timeframe, estimated net total, signed venue contributions and proportional source-colour bars. Partial or unavailable sources are labelled explicitly and the total becomes a subtotal when coverage is incomplete. The card stays inside the chart and moves below the bar when there is no space above. Detailed source diagnostics remain available through the chart diagnostic API. The current host candle remains provisional until the candle closes.

This is an estimate of long-side or short-side activity. Open interest is one side of matched positions and these inputs cannot distinguish whether activity opened or closed risk. Price-based classification also depends on fresh price observations at both boundaries; flow-based classification requires complete trade coverage across the same interval. Hyperliquid and Bybit OI timestamps are collector-sampled. Bybit uses the single-side BTC field rather than the two-sided OI total. Collection and history depend on the staging recorder's availability and start time.

The controlled Playwright fixture intercepts the positioning endpoint explicitly; it is not a runtime fallback. Earlier display fixtures captured the separate-pane version. The current combined pane keeps the same observed-only and visible-range rules, with one shared request and independently scaled Longs and Shorts bands.

Historical live staging evidence from 2026-10-19 was collected against the separate-pane version. It confirms observed updates and bounded retained history at that time; it is not acceptance evidence for the combined pane and makes no frame-rate claim.

Indicator pane order, including placement relative to the main price pane, is saved in the browser workspace and restored on refresh. Reordering does not change positioning data or source subscriptions.

Global settings can project the bars in base BTC or estimated quote notional. Quote conversion sums each classified interval’s BTC quantity multiplied by that interval’s recorded ending price; a missing price makes the quote value unavailable. Binance and Bybit use USDT and Hyperliquid USD quote prices, with combined quote totals labelled USD quote (no FX conversion). Hover cards show both quantities, put the selected currency first, and retain source quality. The global choice is display-only and does not replace saved indicator settings or the BTC source history.

## Price-area hover and drawing

Hovering a Net Longs/Shorts source bar previews a shaded band on that chart's price pane. Double-clicking the bar saves an editable native rectangle from the candle to the visible right edge at the time of saving. The rectangle uses the existing Object Tree, undo/redo, instrument-scoped workspace persistence and drawing settings. Moving off the positioning bar, changing its sources/method, hiding the panel or changing instruments clears the transient preview; previews do not change autoscale or create objects.

The band is explicitly a **chart candle 70% executed-volume value-area proxy**, not identified entry prices. The current recorder has no entry-price distribution attributable to estimated net longs or shorts; boundary prices alone do not establish it. The area grows contiguously from the largest-volume price row until at least 70% of the candle's recorded base volume is covered. VAL/VAH use the selected outer row edges, including the upper row width. Ties expand toward the lower row first. Row aggregation therefore controls precision. Partial/gapped observations stay labelled partial; empty or capacity-limited profiles produce no zone.

Visible positioning panes on supported Binance chart instruments share the existing bounded Footprint data subscription even in candle display mode. Hovering does not fetch or construct an OHLC-based synthetic profile. A missing retained profile, or a chart venue without supported price-volume data, shows unavailable VAH/VAL and cannot save an invented zone. In a multi-venue pane, each preview identifies the hovered positioning source and the reference chart instrument: the reference candle's value area is a proxy, including when those venues differ. Saved drawings preserve this context and the original candle interval in their metadata. This interaction requires no server deployment.

Positioning bar widths follow the host chart's rendering geometry: the snapped candle body in candle mode, or the full bid/ask Footprint column (including its central gutter) in Footprint mode. Stacked sources fill that width; grouped sources divide the same column into stable venue slots. Zoom and Footprint layout settings update the widths without the former 64px cap.

Hover price lines and saved positioning zones use the same colored numeric tags in the price-axis column as ticker rays. Nearby zone boundaries keep separate readable tags. Chart captions and positioning tooltip source rows use the venue toggle's 12px icon and compact `BN[P]`, `HL[P]`, `BY[P]` (or `BN[S]` for a Spot reference) notation. Captions sit near the right end; the tooltip identifies the reference chart candle separately. Original source/interval provenance remains in saved zone metadata.

Automatic positioning-zone captions contain only the source venue icon, badge and signed captured amount, for example `BN[P] 1.25 BTC` or `HL[P] 100K USD`. Base/quote follows the indicator's effective currency preference, including the global override; saved zones retain both quantities so switching display does not revalue them at the current market price. The amount is the hovered venue's contribution, not the combined stack. Proxy/coverage/reference detail remains in the tooltip and saved metadata. Older zones without captured quantities show N/A rather than an inferred amount. Author-written custom captions remain intact.
