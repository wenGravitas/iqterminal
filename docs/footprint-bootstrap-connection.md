# Bootstrap data is separate from live delivery

The five-round Pi font comparison exposed a current-only control case that
displayed live after a6.17sbootstrap response but received zero execution packets
and sent zero ACKs. The independent source watermark advanced89executions between
health reads. Healthy HTTP/source metadata did not prove that this browser's
new live transport delivered. The case remains failed evidence, not a finite
subset omitted from the result. Its precise network/serving cause is unresolved.

A fresh authoritative bootstrap still seeds and paints its data/cursor, but its
initial connection status now says loading and explicitly awaits the live
execution stream. A stale source remains stale. The existing valid stream
execution/health handlers independently establish live/catch-up status. No extra
source replay, exchange connection, socket reset or accumulation is introduced.
Historical bars and Footprint Totals remain displayable while connection
confirmation is pending. Existing shared live subscriptions retain their live
state when another viewer joins.

The legacy history path also retains the pending transport message and removes
its own obsolete history suffix before refreshing history status. A historical
response cannot replace awaiting-live wording with a claim of durable live
updates. Recovery from a current build failure returns to awaiting confirmation;
job readiness alone no longer certifies a live feed.

The focused old-source counterfactual fails. The repaired forming-bar test
displays its seeded data before stream confirmation, then applies one real
fixture execution without duplication and becomes live. Retry tests now require
actual stream input before asserting a healthy live feed; current-job recovery
without stream input correctly remains awaiting confirmation. Canonical cells,
base/quote projection, history coverage and accumulator arithmetic are unchanged.

This is status correctness, not evidence that initial current loading meets its
latency target. Rollback is the bootstrap/legacy status-message change and client
rebuild; no backend, source, collector or cursor operation is needed.
