# Handoff

Terminal T0 uses the official, exact-pinned OpenAlgo Charts 2.6.0 Canvas2D renderer through a narrow adapter. Binance BTCUSDT Spot, Binance USD-M perpetual and Hyperliquid BTC perpetual candles remain in the dedicated public market-data worker. Spot and perpetual markets have independent feed identities and connections; legacy layouts without a market field remain USD-M perpetual. The vanilla DOM **Indicators** panel adds local, versioned OpenScript studies in separate bounded workers, with built-in EMA, candle volume and Binance USD-M quote-depth examples. No trading actions, React UI, general JavaScript runner or feed-worker script execution were added.

The 59 unit checks, 13 Chromium browser checks, diagnostic production build, direct five-interval candle checks for both venues and live Binance depth/coverage probe passed. Editor and chart screenshots at 1366×768 and 1920×1080 show the active EMA, volume and depth outputs; the fixture label identifies synthetic candle data while depth remains a real public feed. The latest supplemental run reaches the eight-study worker cap; its bounded CPU profile is recorded separately from primary chart-only timings. See [verification](verification.md) and [the milestone evidence map](openscript-milestone.md).

Performance is recorded separately for candle-only and active-study workloads on the Raspberry Pi ARM64 Chromium host. The current candle-only response-paced run reported p95 RAF 16.8/33.3/16.8 ms at 1/2/8 charts, compared with 166.7/50.1/116.7 ms before OpenScript was added. Action counts differed (4/12/12 vs 37/29/46), making the comparison noisy and unsuitable for a speedup claim. The latest clean supplemental study run reports p95 RAF 16.8/33.3/66.7/66.8 ms for 3/4/8/8 active studies, with maximum long tasks 0/0/73/88 ms. The eight-active-study 60 fps target is unmet; the separate CPU profile is instrumented and not used for those figures. The profile showed chart/text rendering and worker-result handling as main-thread inspection targets. Full-column study-result transport remains a follow-up optimization.

The exact OpenAlgo Charts and OpenScript package integrity, notices and local patch are recorded in the lockfile and third-party notice. Frozen lockfile resolution passes; a full frozen install remains unverified in this environment because the package-manager tarball was unavailable offline and registry requests timed out. Vite also reports a 500 kB main-chunk warning. Firefox was not verified on this host due to a compositor framebuffer error.

True footprint work still needs a classified trade stream and bounded per-price aggregation; OHLCV cannot reconstruct trade-side volume. Any future scripting work should remain behind the isolated study host and must not share the market-data worker.
