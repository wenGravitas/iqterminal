# T0 boundaries

Chart metadata uses a native `.chart-footer` outside `.chart-stage`, so resize observers give OpenAlgo only the remaining canvas area. Heatmap collection metadata and connection status have separate compact rows below the native time axis and footprint statistics. Empty/error status moves into the stage as a centred overlay; Retry remains an accessible native control. Footer text truncates on narrow panels with full-text tooltips. This layout does not change feeds or render scheduling.

`main.ts`, `layout.ts`, `panel.ts`: native DOM shell, typed candle panel registry, create/update/dispose, versioned validated Dockview JSON with debounced storage. The chart toolbar's searchable Indicators dialog adds default studies; Manage library opens the lazy OpenScript editor. OpenAlgo legend source/settings controls route to the exact pinned attachment or an isolated per-attachment settings form, and native visibility/removal events update persisted worker ownership. Bad/unknown/oversized layouts fall back to the initial pair. Zero panels is a persisted valid empty state. Storage contains configuration/layout only. Eight panels maximum. Dockview handles free docking, tab grouping, reordering and splitters; floating/popout features are disabled or unexposed.

`feed/worker.ts` runs one dedicated worker per browser tab. `service.ts` owns independent public-data sockets per active market connection, ref-counts exact venue/market/native-symbol/interval series and de-duplicates in-flight history. Binance Spot BTCUSDT (`market: 'spot'`) and the existing Binance USD-M perpetual (`market: 'perpetual'`) therefore have separate history, WebSockets, queues, caches and subscription identities. A missing market in a persisted legacy series canonicalizes to `perpetual`; Hyperliquid only accepts `perpetual`. The instrument metadata names base BTC and quote USDT and leaves Spot settlement/collateral unset. Unused series are immediately evicted (zero inactive cache). At most eight active series, 5,000 bars each, 512 pending distinct timestamps per series; overflow sends a new snapshot. Pending patches flush at 20 batches/second. Structured cloning small patch messages preserves ownership; no canonical buffers are transferred. Initial history is about 1,000 bars. Cache/model pruning leaves a 128-bar slack after rollover, preserving the viewport's timestamp anchor.

Binance Spot history uses the public market-data-only `data-api.binance.vision/api/v3/klines` endpoint; its live `btcusdt@kline_<interval>` stream uses `data-stream.binance.vision`. Spot and USD-M use the same native candle tuple/event fields, and both normalize volume to cumulative BTC base-asset quantity. Spot does not use the futures REST or WebSocket endpoint. The selector, panel title/metadata, editor target, script context, persisted identity and depth capability keep Spot distinct; EMA and candle-volume studies still use the selected chart's native OHLCV. Depth remains USD-M perpetual only.

The same feed worker owns one Binance BTCUSDT USD-M diff-depth socket and one 1,000-level REST snapshot for all active depth-study bands. It buffers websocket updates until a snapshot bridges their sequence IDs; gaps invalidate the book until a fresh snapshot bridges again. Only requested 0.01%–0.25% bands (0.01% increments) are sampled, once per second. Each series is a conservative base-BTC or quote-USDT sum inside the band. A side is null when the snapshot edge does not cover the whole band. Depth-study history is bounded by 90,000 total observation rows across bands. Hyperliquid depth is not connected to this study.

`heatmap-service.ts` independently reference-counts consumers of the existing synchronized depth service. `heatmap-model.ts` integrates host-observed piecewise-constant quantities into bounded, engine-independent UTC tiles; it preserves conservative snapshot edges and synchronization epochs. Equivalent resolutions share collection and one acknowledged publication queue. `chart/orderbook-heatmap.ts` is a repo-owned bottom-layer public OpenAlgo primitive, with quantity-first LOD, fixed candle-slot timestamp/logical mapping and no autoscale contribution. `heatmap-controls.ts` owns native controls; panel configuration retains settings across chart modes without changing study inputs. An attached Footprint derives heatmap resolution from its price level, including while hidden; both use fixed lower-bound grids. Removing it restores the independent heatmap grid. Grid alignment is part of the shared collection key, and tiles carry their lower-bound offset. See [the heatmap contract](orderbook-heatmap.md) for weighting, coverage, limits and ownership.

The same worker owns the Binance BTCUSDT USD-M `aggTrade` connection for session Footprints. `footprint-service.ts` shares a configuration across matching consumers and bounds retained bars, price cells, reordering state and duplicate IDs; `footprint.ts` classifies maker-side observations, aggregates them on integer tick rows and publishes revised UTC bars with explicit coverage. The IPC path allows one unacknowledged envelope per configuration and coalesces later revisions until the client acknowledges delivery. It never reconstructs executions from candles or requests historical trade backfill. See [session Footprints](footprints.md) for field semantics, coverage and limits.

Adapters validate identity, finite OHLC relationships, cumulative BTC volume, UTC millisecond open time. Reconciliation uses timestamp keys: history revision=0; Binance live revision=exchange event time; Hyperliquid live revision=trade count because candle messages lack a separate event sequence. Higher revision wins, equal revision uses last receipt unless it would reopen a closed candle. Equal-count Hyperliquid updates therefore have an explicit receipt-order tie-break; authoritative ordering cannot be inferred beyond the provided fields. Live can arrive during history; history cannot replace a live revision. Volume is replaced, never summed. Initial/repair snapshots are sorted and idempotent. Client subscription tokens and worker request generations reject obsolete selections/responses, including switch-away-and-back races.

Reconnect resubscribes and fetches recent overlap/gap with the same merge rules, retaining existing history. Repair is limited to the latest 1,000 intervals, matching T0's bounded recent-history scope; no infinite backfill. History timeout 15s, bounded backoff 1–30s with jitter, five automatic transient retries; hard HTTP rejections require Retry. Browser WebSocket errors hide handshake HTTP details, so repeated unsuccessful connects also stop after five. Binance uses protocol heartbeat handled by the browser and proactively rotates before the documented 24h lifetime; no application ping. Hyperliquid sends its documented ping every 25s and checks message freshness. Socket-open does not imply live: valid candles drive last-update time, 15s silence becomes stale. Offline/online and independent venue failure are handled.

`chart/openalgo.ts` is the narrow adapter around official, exact-pinned `openalgo-charts@2.6.0`. Worker candles use UTC milliseconds and Float64 prices; the adapter converts timestamps to the library's UTC-second `Bar` contract. Initial and repair snapshots replace the series once; live and historical corrections use incremental updates with their source marked, and the adapter bounds its ordered index and rendered series to 5,000 bars. The chart's own time/price navigation, cursor-anchored zoom, axes, autoscaling, crosshair and OHLC rendering replace the retired custom renderer. A disposable plot-wheel listener supplements OpenAlgo 2.6.0 time zoom with supported `PriceScale.scaleAtY`, using the same normalized wheel factor and cursor anchor. Price-axis wheel gestures and Shift/horizontal-wheel panning remain native. Wheel zoom takes the hovered pane into manual price scaling until Latest/reset. Canvas2D is selected explicitly for the shipping build based on same-host measurements; no optional WebGL backend is imported. Docking, resize and repair preserve the user's viewport. Latest/Home/double click restore the newest candle and price autoscaling.

Footprint mode lazily mounts the optional OpenAlgo profile primitive and a separate execution-OHLC index series. The index candles are transparent but participate in price autoscaling; the regular candle series remains the only series in candle mode. The worker retains base quantities and actual execution-price notional sums together. A small display projection selects BTC or USDT quantities at this boundary without restarting collection or changing execution OHLC, shared feed ownership or OpenScript inputs. The adapter converts worker bars at this boundary and sends only the visible interval plus neighboring bars to the primitive. Viewport changes refresh that slice through the shared dirty-visible-chart scheduler; unchanged visible time/revision keys skip another primitive `setBars`, including patches outside the viewport. Hidden panels retain bounded data with one pending visual refresh and catch up on activation; display options change rendering without restarting aggregation.

`chart/scheduler.ts` is the single application RAF scheduler for dirty visible charts. Hidden tabs retain bounded data without chart frames or readout changes and catch up on activation. OpenAlgo owns and releases its internal observers, inputs and canvases on `destroy()`; the adapter also removes its pending callbacks. Resize and docking preserve chart instances. HMR/page disposal terminates the worker, timers, chart observers and inputs.

## OpenScript studies

The dockable **Indicators** panel is a vanilla DOM editor loaded only when opened. It uses exact-pinned `openalgo-script` 0.8.1 to compile OpenScript language version 1 study source and execute it in one dedicated worker per attached study. A worker compiles its source on its first `start`; incremental append/forming-bar patches and later history rebuilds reuse that worker's compiled program. A shared in-memory LRU lets new or replacement workers reuse only a successful worker-produced artifact for the exact same source and the current runtime/host contract. It holds at most 16 entries, 4 MiB total and 512 KiB per entry; sources remain limited to 100,000 UTF-8 bytes. A source miss, oversize artifact, version change or eviction compiles in the worker. Each worker still rechecks the cached program against host restrictions and engine validation, reconstructs the source index and resolves new settings before execution. Failed source/results never enter the cache. Package imports contain source and metadata only: the application validates source in a worker, compiling it or reusing only an exact source-keyed, worker-produced cache entry, recomputes the SHA-256 revision hash and source-derived capabilities, then compares them with the package fields. A package-supplied program field is discarded and never loaded. Language/package format and runtime compatibility are explicitly pinned to language v1 and runtime `0.8.1`; `iqcap-v1` versions the host capability contract used in the cache key.

The compiler/engine is not imported on the page's main thread; only validated plot metadata and numeric results cross from the worker to the chart adapter. The study worker never shares the market-data worker. It receives a bounded candle history and whitelisted numeric-series values, and has no file, network, account, order or trading host functions. It does not execute JavaScript or generate code with `eval` or `new Function`.

The host accepts only read-only study programs with 1–8 line/histogram plots, at most four fills and 16 inputs. It rejects strategies, requests, orders, alerts, tables, levels, script-authored markers, bar colours, backgrounds, candle-shaped output and per-bar colours. For a line plot, the adapter derives a native small dot only when a finite value has no finite neighbour on either side; the dot uses that plot's resolved colour and exact bar time/value. It retains the latest 64 isolated samples per study and leaves all null gaps unchanged, so sparse live depth appears without fabricated continuity. Source is limited to 100,000 UTF-8 bytes; history and each result column are capped at 5,000 bars; script loops are capped at 128; runtime work is capped at 40,000 steps/20 ms per call, arrays at 5,000 elements, strings at 2,048 characters, drawings and requests at zero. There are at most eight live study workers plus one temporary replacement candidate; startup is limited to 2.5 seconds, patch calculation to 500 ms, and queued patches to 512 distinct timestamps. A candidate is applied only after it compiles and calculates; a failed edit leaves the previously applied study running.

The source feed's candle open time remains an integer UTC epoch-millisecond value through script execution. The `closed` bit distinguishes confirmed historical/closed bars from a forming tail; realtime appends and tail revisions pass the matching confirmed/forming flag into the engine. The chart adapter converts returned millisecond timestamps to integer UTC epoch seconds to align outputs with OpenAlgo chart bars. Only the four declared v1 numeric-series keys are copied to a `numericSeries` row, and each cell is finite numeric data or `null`; unknown keys and non-finite values become unavailable. The source capability list is derived from compiled source-input defaults and options, not from an imported manifest. The package boundary accepts only `ohlcv` and the optional `iqterminal.depth.series.v1` capability, verifies the exact derived list, and enforces language/runtime versions and source hash.

The engine's EMA uses the library's simple-average seed and first returns a value at bar `length - 1`. Appending and updating the forming bar are incremental and preserve engine state. A snapshot/history repair or other explicit rebuild reloads the engine over the current retained last 5,000 bars; stateful calculations then restart from that bounded window. Results that would require data before the retained window cannot include that discarded history. The worker currently returns bounded full timestamp/value columns for each incremental result, and the chart adapter validates and aligns those columns against the current chart bars before scheduling a redraw.

Built-ins cover EMA, candle volume in BTC, and Binance USD-M depth. The depth source names are `iq_depth_bid_base_v1`, `iq_depth_ask_base_v1`, `iq_depth_bid_quote_v1`, and `iq_depth_ask_quote_v1`; the first pair is BTC, the second is USDT. For a band `p` percent, the synchronized book midpoint is `(best bid + best ask) / 2`; bid levels with prices from `mid × (1 − p/100)` through `mid` and asks from `mid` through `mid × (1 + p/100)` are summed inclusively. Base outputs sum BTC quantity; quote outputs sum `price × quantity` in USDT. The band setting is a percentage number from 0.01 to 0.25, in 0.01 increments. The book samples active bands once per second after a Binance snapshot bridges the buffered diff stream; a sample records its UTC millisecond observation time and midpoint and is assigned to its enclosing candle interval. Only the latest sample in a candle interval is used. Snapshot coverage is conservative for each synchronization epoch: if the snapshot boundary does not cover the complete bid or ask band, that side is `null`; if a sequence gap invalidates synchronization, no sample is made until a fresh snapshot bridges the stream. No historical depth is fabricated: values are available only from the actual collection start, with at most 3,600 one-second observations retained per band. The engine receives `none` and plots preserve gaps when no sample exists. Missing depth is never treated as zero, interpolated or carried forward. Status distinguishes unsupported Hyperliquid from incomplete live Binance snapshot coverage.

Users can edit a built-in copy, import/export a plain `.oscript` source, or exchange an `iqterminal.openscript` JSON package. A package contains validated metadata, one immutable source revision, its SHA-256 source hash, language/runtime versions and capabilities; import validates source in a worker, recompiling or reusing an exact source-keyed trusted worker artifact, and recomputes those fields instead of trusting the package declaration. User scripts and revisions stay in IndexedDB on the current browser. Each chart layout stores only an attachment ID, revision hash, visibility and bounded inputs, then restores that exact revision from local storage. IndexedDB schema v2 creates the missing script store when upgrading older installations; damaged rows are hidden with a warning. Storage failures are reported in the editor without stopping candle feeds. The source, revision, script count and local-storage byte budgets are enforced at save/import boundaries.

## Later milestones, not implemented

Other venue adapters and additional footprint-derived studies remain later milestones. The ordinary direct mode keeps executions session-local and separate from native candle history and OpenScript inputs. The explicit [staging development mode](staging-market-data.md) adds durable Binance USD-M aggregate history through the existing worker, shared pure accumulator and private SSH proxy. Native script candle inputs remain distinct.

Rust/WASM may help measured bulk aggregation, backfills or numeric kernels using batched calls across the existing DOM-free boundary. Host rendering remains owned here. OffscreenCanvas/WebGPU are later benchmark questions, not assumed speedups. AI panels would request explicit bounded timestamped market context, with requests entirely outside the feed/chart hot path.

## Appearance

`theme.ts` validates the independent `basis.theme.v1` localStorage choice (`light` or `dark`), follows the device light preference only without a saved override, and falls back to Dark. System removes the override. Device and cross-tab storage changes update the selector, root semantic tokens and Dockview colour scheme. Storage/media failures are tolerated; the controller aborts its listeners on teardown. The tiny public `theme-init.js` runs before CSS/app startup to apply that same selection without a wrong-theme first paint; the standalone Licences page uses it too.

Chart adapters consume the initial palette and a disposable appearance event subscription. OpenAlgo's public `setTheme`, `setGridOptions`, series `applyOptions`, and Footprint `setOptions` recolour existing instances; they do not recreate chart/panel/feed/indicator state. Hidden charts retain the palette but still paint only through the visible-panel scheduler. Author-selected study colours stay intact. Heatmap label contrast uses the actual composited chart background; its quantity palette and normalization remain unchanged. No layout schema change is needed.


## Axis-bound grid

`chart/axis-grid.ts` supplies a primary-price-pane background primitive using OpenAlgo 2.6.0's public scales and primitive API. The library's fixed-pixel grid is disabled. Horizontal lines use the primary readout price scale's tick values; vertical lines use actual candle indexes and the installed UTC time-axis selection/collision policy, including day boundaries and irregular session Footprint times. The small adapted selection routine is attributed in the app's Licences page and must be checked against native axis labels on a library upgrade. It contributes no autoscale data, synthetic bars or separate render loop. The existing visible-chart scheduler repaints it with the scales; removal clears its owned geometry and host reference.

`PanelConfig.grid` is a validated boolean, defaulting to true for legacy or corrupt values. The shared Chart settings gear toggles it immediately and persists it through existing workspace parameters. Changes preserve feeds, chart instances, viewport, heatmap collection and studies. Only grid visibility is configured here; directional/colour customization is outside this change.


## Fixed price bucket boundaries

Executed footprint cells and resting heatmap rows use lower-bound integer-tick buckets: `floor(tickIndex / rowTicks)`, anchored to zero rather than the first execution or the displayed viewport. A $25 row at $82,800 covers [$82,800, $82,825). `FootprintCell.price` is the canonical lower bound. The OpenAlgo adapter adds half the width for the library's centre-based cell geometry, translates hover back to the canonical bound and reports the exclusive upper edge. Pulse overlays use [lower, lower + width] geometry. Actual execution OHLC, volume, delta and exact USDT notionals are unchanged.

Heatmap collection uses the same fixed bounds. Matching Candle and Footprint resolutions now share the same retained collector and depth source; the Footprint display flag only disables visual price-row merging. No session data is persisted, so refresh starts collection under the new rule without a stored-data migration. Saved widths/settings remain compatible.

### Footprint presentation wrapper

`chart/terminal-footprint.ts` extends the installed OpenAlgo 2.6.0 Footprint through its public setBars/setOptions/draw boundary. It retains upstream outputs and statistics, with a central candle gutter and translated cell hit testing. A cached Canvas2D forwarding context changes cell font assignments and multiplies path-fill alpha for cell backgrounds, preserving text alpha and candle/footer fillRect operations. It fits fonts using the actual row scale and current column width, with longest compact quantities cached at bar installation. Heatmap quantity labels are suppressed where an execution cell occupies the same candle/price row, so translucent foreground cells do not reveal competing figures beneath bid/ask text. Liquidity backgrounds and hover observations remain unchanged. The check uses canonical footprint time/price bounds, not stale primitive hit geometry.

## Durable staging liquidity

Explicit staging mode routes supported heatmaps to `feed/staging-heatmap.ts` inside the existing feed worker. The chart adapter reports its visible time/price bounds; the worker coalesces and aborts generation-scoped requests, adapts resolution within a rendering budget and replaces bounded historical/live tiles by identity.
