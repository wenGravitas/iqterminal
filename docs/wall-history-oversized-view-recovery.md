# Oversized Order Walls viewport and recovery

The foreground screenshot on 17 November 2026 shows a requested range of 14 November 16:15 through 17 November 06:27 UTC (about 62 hours), with `Prepared wall discovery HTTP 400: Invalid bounded wall source version request`. Backend `validateWallSourceRequest` permits at most 48 hours per source-proof request. A 15-minute candle interval does not constrain the visible range to 30 hours. The screenshot and validator establish this range rejection; no failed-request query capture was available to attribute another invalid field.

The client now rejects an oversized prepared-history request before HTTP admission with an actionable 48-hour/zoom-in message, without changing requested coverage, source proofs, server limits or financial output. It does not claim the missing history was loaded or the source unavailable.

A deterministic regression reproduced a second defect: after a history failure, narrowing a contained viewport from 62 to 47 hours left the original failed job attached. The old offscreen-loading optimization only retargeted unsettled jobs and required a 25% reduction. The fix admits the narrowed failed viewport regardless of that threshold, while preserving the current subscription and any displayed historical presentation until validated replacement. Identical viewport notifications do not retry the same failed job. Existing continuation and full-replacement validation remain unchanged.

Validation: the recovery regression failed before the patch (one historical request instead of two); all 168 focused tests across archive service, admission, prepared history/projection and repeated continuation pass afterward. Cases include exact 48-hour acceptance, rejection immediately above it without fetching, preserved warm walls during failed-view narrowing, and unchanged-range notification deduplication. Typecheck passes. These are deterministic checks, not a new live financial or foreground acceptance claim.

For the existing manual build, zoom to approximately 30 hours (about 120 candles at 15m), then remove and re-add Order Walls to discard the old oversized request. Resume alone can repeat the original failed range.
