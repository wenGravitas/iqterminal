The server endpoint is **Tailscale SSH**, verified `RunSSH=true`, installed version1.104.5. Its SSH sessions terminate in `tailscaled` userspace networking, so ordinary server kernel `ss` has no corresponding TCP/22flow. The sampler therefore records the actual shared/session `tailscaled` processes; **server per-flow RTT/RTO/retransmission counters remain unavailable**, not zero. Active path snapshots show direct UDP endpoints and changes in the Pi's observed public UDP port; the Relay fields are fallback metadata, not proof the active traffic used DERP.

Current SSH had **zero major faults** in both windows,0.48/0.29CPU-seconds and3.667/3.447seconds of accumulated scheduling wait across300seconds. The largest observed scheduling-counter increments were599/585ms; these counters have deferred updates and are not exclusive one-second phases. Client TCP retransmission deltas were5/2, max RTO2384/2752ms, and max sampled send queues2300/4888bytes. These counters do not identify the missing server-side/userspace queue. Zero retransmissions and every probe meeting4s are not release gates.

The Pi nevertheless had substantial whole-host swapping: baseline10,800pages in/99,545out; verification207,476in/263,762out. SSH major-fault evidence weakens direct SSH paging as the explanation, but does not exclude all memory-pressure effects. **Pi CPU/memory/I/O PSI files are absent**, so pressure is explicitly unavailable there. Server PSI was recorded; CPU some/avg10 maxima13.64/9.19%, memory0/0%, I/O19.27/20.78%. No physical/Tailscale interface error/drop increase was observed; three unrelated client Docker bridges accumulated10TXdrops each. User processes were not removed, swap/caches were not changed, and no global network configuration changed.

The sole tested explanation/remedy was renewal of the long-lived owned current SSH connection, with exactly the existing flags/target and the same retained browser workload. It **failed to establish recovery**. Confirmed/applied cursor progress is used here instead. The workload helper did not retain every per-pane live-warning transition, so no blanket UI-warning correctness claim is made.
