# Liquidation Map retirement display

Backend model `conserved-cohorts-v4` / history version 2 supplies all recorded
stock-change boundaries and optional `validUntil` times. `mapColumnEnd()` clips
to the earliest explicit end or successor. The first +50s removal in a four-minute
bucket must survive a later +150s empty snapshot. Existing absolute grids,
worker acquisition/cache bounds, primitives and dirty-chart scheduling remain.

The latest profile is separate from historical columns. Its source/receipt and
native mark freshness gates also govern profile hover/totals. Expired latest
exposure disappears without deleting past exposure. Filtered profile rows are
cached until the next freshness boundary. Automatic heatmap intensity uses
visible time/price rows; automatic profile width and colour use visible price
rows. Fixed intensity/profile scale is explicit. Offscreen price outliers do not
flatten visible data. Tooltip provenance includes timestamp quality, native mark
age, quarantine quantity and recorded interval end.

Validation:

```
pnpm exec vitest run tests/liquidation-map.test.ts tests/liquidation-map-service.test.ts
VITE_DATA_MODE=staging VITE_HISTORY_TILES=1 VITE_DIAGNOSTICS=1 pnpm build
pnpm exec playwright test tests/browser/liquidation-map.spec.ts
```

`tests/fixtures/liquidation-map-retirement.json` is explicitly fixture-only,
generated by the backend's `ops/demo-liquidation-map-retirement.ts --fixture`
command through the actual journal/runtime and restart replay. The headless
Chromium test displays the band before crossing, after crossing/rebound, and
after reload. Images: `/tmp/iq-map-retirement-before.png`,
`/tmp/iq-map-retirement-rebound.png`, `/tmp/iq-map-retirement-reload.png`.
Fixture prices and timestamps are shifted for chart alignment only. These are
correctness demonstrations, not live liquidation prediction or Pi frame-rate
acceptance measurements.

Old periods without native mark evidence cannot be retrospectively repaired.
The server reports each venue's retained `markHistoryFrom`; v3 historical
snapshots retain their original provenance. Dense changes exceeding the existing
IPC/cache budgets first coarsen the absolute price grid, with the effective grid
shown in the status line. The learned grid remains stable through navigation and
warm reopening. This preserves stock totals and every known removal boundary.
At the maximum grouping, capacity errors retain loaded coverage; reduce lookback
rather than silently discarding retirement boundaries.

The local development and static proxies give Liquidation Map its own single-
socket `map` pool. It bypasses bulk wall admission and idle sockets from other
upstreams; the backend retains its two-request admission limit. The independent
proxy fixture tests keep both bulk lanes occupied while map requests complete.

For v2 history, the 8MiB payload budget estimates resident cell objects plus
full per-column metadata. Repeated immutable cell strings, scenario catalogs
and quality arrays are shared explicitly. The 32MiB cache, 100k IPC-cell and
8MiB response-page bounds remain. Nested price coarsening happens inside the
worker on already downloaded columns; remaining pages use the coarser grid. It
never sums stock through time or drops the first removal. The effective price
grid is shown in the status line.

An explicit real-source acquisition check is available with
`IQ_MAP_LIVE_SMOKE=1 pnpm exec vitest run tests/liquidation-map-live.test.ts`. It
uses the existing private staging route and writes `/tmp/iq-map-live-acquisition.json`.
Ordinary tests skip it. It measures total cold elapsed time, warm cache reuse,
transport size and resident budget; it does not certify Pi frame intervals.
